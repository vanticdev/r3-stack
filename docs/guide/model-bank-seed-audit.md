# Model-bank seed audit (2026-10-29)

Each row is a model record; the Raspberry Pi row covers the 1/2/4/8/16 GB catalog variants. All purchased component types in the RC-car and bundled off-the-shelf catalog, all connector types and the RC-car plain fastener sizes are represented. A missing source is a search/proxy record, not a fabricated download.

Live keyless proof: the Pololu official resource-page ingestor downloaded D36V50Fx STEP (`cdcc9e55ba1de3adfb59c330732e107a6419216c4c6f5f16396c5423757c5155`). The installed KiCad ingestor found both XT60 STEP models. The official Raspberry Pi STEP checksum was verified and both vendor models converted to GLB/STL. No Onshape API-key credentials were available, so translation/import/assembly endpoint behavior was tested with offline contracts only.

Pi measured bbox: **88.500 × 57.630 × 18.976 mm**, catalog: **87 × 56 × 17.6 mm**. Y exceeds the 1.5 mm tolerance. This is an explicit `model_datasheet_mismatch`, not a passing result. Pololu measured **25.400 × 25.400 × 9.475 mm**, within catalog tolerance, but holes/interface frames remain unreviewed. No imported model is claimed fabrication-ready.

Public source discovery was bounded: the catalog mappings, installed KiCad library, official resource pages and the named vendor searches. Public Onshape search needs API credentials; account-gated databases are not scraped. “Not pinned” does not assert that no model exists anywhere.

Validation on `r3/modelbank`: the full `pytest tests -p no:randomly -q` run passed
**577 tests in 1085.52 s (18:05)**. The final model-bank/CAD regression run passed
**38 tests in 8.54 s**, and web `npm run typecheck` passed. The RC-car
`assembly,model,cad` validation intentionally reports **1 error and 56 warnings**:
the error is the Pi datasheet mismatch; the purchased-source gaps remain warnings.
No thresholds were weakened and no other lane's robot design was changed.
