# Model-bank seed audit (2026-10-29 follow-up)

The same **70 records** were re-audited: **13 downloaded-source records / 57
proxies before → 26 downloaded-source records / 44 proxies after**.
All 26 active source URLs were fetched anonymously again during this run and
matched their pinned SHA-256; no model bytes or cache files are committed.
“Downloaded source” does not mean qualified CAD: the Pi has reviewed outline/hole
features, 23 other records still need interface/feature review, and **two new
sources fail their envelope check** (DS3218 and the named XT30U-F download).

The original 57 gaps each have current-run acquisition or a specific written
reason below and in `searched_sources`. Searches covered official manufacturer
resources, installed/upstream KiCad models, public GitHub hardware/standard-parts
libraries (the normal contents/tree and code-search interfaces), and permitted
public model pages. No login-gated model downloads, guessed download
URLs, FeatureScript or agent-authored purchased geometry were used. GitHub code
search hit its rate limit briefly; failed queries were retried after other work.
Onshape public search/native translation remains blocked without API-key
credentials; the browser bridge was not used.

Exact variants matter. NASA's public `XT30_F.step` was downloaded and rejected
for the XT30U-F slot. Its complete provenance and failed comparison are retained
as `rejected_source` search evidence, not as an interchangeable bank model. A
second public file *named* `xt30u-f.step` also measures 15.6 mm long versus the
catalog's 13.6 mm; it is indexed, visibly **mismatch**, and cannot be used as an
approved XT30U-F. Savox SC-0251MG+ CAD was found, but it is not SC-0251MG; no
substitution was made. A bare u-blox chip is not a GNSS breakout board.

## Purchased Pi measurements

[Full Pi measurement evidence](model-bank-pi5-measurement.md): the official STEP
and native B-rep confirm the **85 × 56 mm PCB** and **58 × 49 mm hole pattern**.
The **88.500 × 57.630352 × 18.976 mm overall envelope** includes connector
protrusions and underside parts. The catalog records both meanings separately,
with an offset envelope preserving board-frame hole positions. The 1.5 mm
validation tolerance is unchanged; `r3 models validate raspberry-pi-5-4gb` passes
its bbox/outline/hole checks. Geometry-derived native mate frames still require
review of the nominal 1.6 mm mounting stack versus the STEP's 1.276 mm PCB.

CAD validation reports the newly exposed **DS3218 `model_datasheet_mismatch`**:
the official file's native bounds are **65.192 × 48.100 × 20.039 mm**, including
horn/lead geometry in a different frame, versus the catalog's **20 × 54 × 45.5
mm** component envelope. It requires model-frame/assembly review; no tolerance
was widened. The named XT30U-F has a separate explicit failed model validation.
Unreviewed `interface_frames` remain empty; source acquisition does not bypass
the native import guards. No purchased CAD was sculpted.

`Project.fingerprint()` now includes a content SHA-256 of the catalog, project
catalog overrides and selected bank dataset. Dataset-only edits make release,
status and report evidence stale. Stale CAD/assembly interference evidence cannot
suppress a new model-stage check.

## Reproduction and validation

With the platform Python packages on `PYTHONPATH` and the `models` extra installed:

```bash
python -m r3_orchestrator models search 'Pi 5'
python -m r3_orchestrator models validate raspberry-pi-5-4gb --json
python -m r3_orchestrator models validate servo-digital-20kg --json  # intentional mismatch
python -m r3_orchestrator models validate connector-xt30-female --json  # intentional mismatch
R3_ONSHAPE_TRANSPORT=api-keys python -m r3_orchestrator validate -C path/to/project --stage assembly,model,cad --json
python -m pytest -q
```

Build-only evidence: `build/modelbank/url-verification.json` records the successful
live URL/checksum re-fetches; `pi5-dimensions.png` shows the board, connector overhangs, underside parts and holes.
No GUI was launched. Verification-only packages installed in the shared venv were
`cadquery-ocp` and `python-fcl`; `rarfile` is now part of the optional `models` extra.

Final validation: **94 targeted tests passed** (41.99 s), followed by the full
`python -m pytest -q` suite: **594 passed** in 1070.83 s (17 min 50 s).
The two explicit source-envelope failures above are retained as measured data;
the test suite verifies their rejection rather than bypassing it.
